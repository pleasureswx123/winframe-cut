# 窗序 · 精密下料工作台

**绘制矩形窗型，自动计算型材和玻璃尺寸，再生成原料采购与切割方案。**

窗序面向门窗尺寸设计与下料准备，支持电脑和手机浏览器。用户设置整窗尺寸、型材宽度和中挺位置后，系统按分区关系生成构件，分别进行型材一维排料和玻璃二维排版。

当前版本支持**管理端发放账号、用户登录、客户与房屋项目管理、独立管理平台和用户数据隔离**。操作平台 `/` 与管理平台 `/admin.html` 共用后端；每个项目包含多种窗型，支持单窗和整项目统一排料。部署、管理员初始化与旧数据迁移请先阅读 [平台部署与使用](docs/平台部署与使用.md)。

## 安装与启动

### 从 PowerShell 7.6.6 启动整个项目

如果当前提示符是 `PS C:\Users\bjtc>`，项目位于 `D:\work\winframe-cut`，依赖已经安装，直接复制执行下面两行（不要复制 `PS ...>` 提示符）：

```powershell
Set-Location -LiteralPath 'D:\work\winframe-cut'
pwsh -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1
```

该命令会构建制作端和管理端，再启动它们共用的后端。两个平台都由 8010 端口提供服务，**不需要分别启动两个前端，也不需要运行 `npm run dev`**。无需手动激活虚拟环境，脚本会使用项目的 `.venv\Scripts\python.exe`。

看到 `Uvicorn running on http://127.0.0.1:8010` 后，在浏览器打开：

| 平台 | 地址 | 登录方式 |
| --- | --- | --- |
| 管理平台 | <http://127.0.0.1:8010/admin.html> | 初始超级管理员：`admin`，密码：`admin123` |
| 制作平台 | <http://127.0.0.1:8010/> | 使用管理员创建并发放的账号 |

首次启动时，系统仅在 `admin` 不存在时创建超级管理员；重启不会重置已有管理员密码。先登录管理平台，进入“用户管理 → 添加用户”，填写用户名、显示名称和初始密码（10～128 位），然后把账号发放给制作用户。制作平台不开放自行注册。

保持启动窗口运行。停止整个项目时，在该窗口按 `Ctrl+C`；下次启动再执行上面的两行命令即可。代码更新后也应先停止原服务，再重新启动。若提示 8010 端口被占用，先找到原来的项目启动窗口停止服务，不要重复启动。

如果这是首次安装、还没有 `.venv` 或 `node_modules`，先按下一节的环境要求安装 Node.js 和 Python，然后执行：

```powershell
Set-Location -LiteralPath 'D:\work\winframe-cut'
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
npm.cmd ci
pwsh -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1
```

首次安装命令会下载依赖，需要网络。依赖未发生变化时，日常启动不必重复安装。

### 环境要求

- Windows 与 PowerShell：仓库中的启动脚本针对 Windows。
- Node.js 22.12+，建议使用 Node.js 24；同时需要 npm。
- Python 3.12。
- Chrome、Edge 等现代浏览器。

运行软件**不需要安装 Blender 或 Blender MCP**。Blender 场景用于建立和核对基准几何，日常计算由后端独立完成。

### 首次安装

下载或克隆仓库后，在项目根目录打开 PowerShell：

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.lock.txt
npm ci
npm run build
.\.venv\Scripts\python -m uvicorn backend.main:app --host 127.0.0.1 --port 8010
```

制作平台：<http://127.0.0.1:8010/>；管理平台：<http://127.0.0.1:8010/admin.html>。首次启动自动创建超级管理员 `admin / admin123`，登录后台“用户管理 → 添加用户”发放制作账号。制作端不开放注册。保持服务终端运行，按 `Ctrl+C` 停止。

`requirements.lock.txt` 和 `package-lock.json` 用于复现依赖；`requirements.txt` 描述 Python 依赖的允许版本范围。

### 日常启动

安装依赖后，双击 [启动窗序.cmd](启动窗序.cmd)，或执行：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1
```

脚本会先构建前端，再启动后端。前端已构建且没有修改时可跳过构建：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1 -SkipBuild
```

8010 端口已有服务时，不要重复启动。更新后端代码需要重启服务；更新前端代码需要重新构建并刷新页面。

## 手机访问

1. 手机和电脑连接同一可信 Wi-Fi 或局域网。
2. 停止原来仅供本机访问的服务。
3. 双击 [手机局域网启动.cmd](手机局域网启动.cmd)，或执行：

   ```powershell
   pwsh -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1 -Lan
   ```

4. 电脑运行 `ipconfig`，找到当前联网网卡的 IPv4 地址。
5. 手机访问 `http://电脑IPv4地址:8010`，例如 `http://192.168.1.20:8010`。

手机中的 `127.0.0.1` 指向手机自身，不能用它访问电脑。如果连接失败，检查电脑服务、专用网络防火墙规则，以及 Wi-Fi 是否启用了设备隔离。

手机设计页使用「画布 / 尺寸参数 / 区域与中挺」切换。点击画布区域后，通过「编辑选区」设置用途或输入中挺坐标，再点击「返回画布」继续操作。密集窗型可用加减按钮放大、缩小，点击「适应画布」恢复视图，也可通过区域列表选取。切割长图与明细表支持横向滚动。

电脑端按「设计窗型 → 核对清单 → 计算排料」操作。玻璃扣减、型材宽度与原料型号可按需展开；修改尺寸后，使用待应用提示中的「应用并更新画布」，或「恢复已应用参数」放弃本次参数编辑。字段校验失败时会展开参数组并定位出错输入框。

构件清单与切割排料均按型材、玻璃分标签查看。排料标签切换保留尚未应用的玻璃草稿；离开排料页面前仍需应用草稿。手机型材原料以摘要卡片呈现，展开后编辑规格、价格和库存；通过「工艺设置」「计算型材方案」快速进入后续步骤，计算成功后自动定位到型材方案。打印只输出当前排料标签中的方案。

局域网模式监听 `0.0.0.0`，用户登录后只能访问自己的客户、房屋与窗型。生产访问需配置 HTTPS、持久数据库和管理员账号，详见平台部署文档。已检查手机尺寸浏览器布局，手机真机兼容性仍需现场验收。

## 火山引擎 veFaaS 试部署

仓库提供 Linux Python 3.12 源码部署脚本。先将部署文件提交并推送到绑定的 GitHub 分支，再使用以下配置创建应用：

| 控制台字段 | 填写值 |
|---|---|
| 代码仓库 / 分支 | `winframe-cut` / `main` |
| 框架类型 | FastAPI |
| 运行环境 | Native Python 3.12 |
| 构建命令 | `sh build.sh` |
| 产物路径 | `.vefaas/artifact` |
| 启动命令 | `sh run.sh` |
| 监听端口 | `8000` |
| 执行超时 | 试运行建议 `240` 秒，同时核对网关请求超时 |
| 实例规格 | 可从 `2 vCPU / 4 GiB` 试运行，按实测调整 |

这些命令替换平台默认的 `uv pip install -r requirements.txt` 和 `python main.py`。产物路径也必须同步修改，不能继续填写 `./`。启动命令相对于发布包根目录执行。

构建脚本先在临时目录安装前端依赖、生成 `dist`，再把后端和锁定的 Python 依赖复制进发布包。环境没有合适的 Node.js 时，从 `nodejs.org` 下载固定版本 24.14.1 并校验 SHA-256。构建环境需要访问 Node.js、npm 和 Python 包仓库；无需 root 权限。运行实例只需要 Python 3.12，不需要 Node.js，也不会在启动时下载依赖。

发布包包含 `backend/`、`dist/`、`.python/`、`run.sh` 和 `start_vefaas.py`，不复制本地数据库、`.env`、Windows 虚拟环境或浏览器测试输出。平台必须包含 `.python` 隐藏目录；启动器会检查关键产物缺失并明确报错。

Python 依赖统一通过平台 Python 自带的 pip 安装，默认使用清华镜像 `https://pypi.tuna.tsinghua.edu.cn/simple`，禁用 pip 配置文件并隔离平台的 `PIP_*` / `UV_*` 环境配置，不再自动选择预装 uv。保留锁定版本，只安装二进制 wheel，不现场编译依赖。单次网络等待上限 20 秒、重试 2 次，整个依赖安装上限 300 秒，超时给出明确错误。

若镜像缺包或访问不畅，可显式修改构建命令为 `WINFRAME_PYPI_INDEX_URL=https://pypi.org/simple sh build.sh`，或指定其他可信 HTTPS 包源。默认不自动回退官方源，避免国内构建节点下载大文件缓慢再次耗尽流水线时限。构建阶段超时与控制台的函数请求执行超时不是同一个参数；不要通过增加请求执行超时来处理构建下载失败。

启动时端口按 `_FAAS_RUNTIME_PORT` → `PORT` → `8000` 的顺序读取，监听 `0.0.0.0`。健康检查路径为 `/api/health`。不要把控制台的执行超时当作算法求解时限：算法仍按原料型号逐个求解；前端当前请求超时为 240 秒。

**此配置用于受控试部署，不代表已经完成面向客户的生产化。** 未设置 `WINFRAME_DB` 时，云端存档默认写入 `/tmp/winframe/projects.db`，只作为临时数据，可能随实例销毁而消失，不同实例也不共享。设置数据库路径本身不会获得持久化能力；当前已实现用户登录、存档归属和权限控制；正式服务仍需 HTTPS、可靠的持久存储及备份。本版本 SQLite 仅支持单实例运行。

```powershell

docker run --rm -p 127.0.0.1:8011:8000 --mount "type=bind,source=$($PWD.Path)/.vefaas/artifact,target=/app,readonly" -w /app python:3.12-slim-bookworm sh run.sh
```

## 从空白窗型开始

### 1. 设置整体尺寸

在「窗型设计 → 设计参数」中点击「新建空白窗型」，填写名称、整体宽高、生产数量，按需展开「型材宽度」设置六类型材宽度，然后点击「应用参数并更新画布」。手机上先进入「尺寸参数」。

新建空白窗型会保留当前尺寸与配置，移除原来的分区结构，初始内部区域为玻璃区。未应用的参数不会用于下料。

### 2. 添加中挺

选择「竖中挺」或「横中挺」，点击目标区域。在弹窗中输入相对于**整窗左上角**的中心线坐标：

- 竖中挺输入 X：距整窗左边的距离。
- 横中挺输入 Y：距整窗顶部的距离。

起点与终点由所在区域边界决定。点击金色中挺可以再次编辑位置。先画的中挺贯通当前区域，后画的中挺在子区域边界处对接。

### 3. 指定区域用途

| 用途 | 自动生成 |
|---|---|
| 安装玻璃 | 一块玻璃和四根压线 |
| 安装窗扇 | 四根窗扇外框，再按窗扇内部区域生成玻璃和压线 |
| 留空 | 不生成玻璃、压线或窗扇 |

窗扇内部可以继续添加中挺。通过区域列表选择父区域，可以替换整个区域用途或移除分隔；涉及已有结构时会提示确认，支持撤销与重做。

### 4. 核对清单

画布下方显示六类型材根数和玻璃块数，数量包含生产樘数。「构件清单」分别展示玻璃和型材，可导出各自的 CSV。

### 5. 配置原料并排料

进入「切割排料」，分别填写玻璃原板和型材整料规格，再计算对应方案。检查采购数量、每块或每根尺寸、旋转、刀缝、切割顺序和余料后，导出加工数据。

## 尺寸与连接规则

### 精度与坐标

界面长度输入最多支持三位毫米小数，计算核心使用整数刻度：

```text
1 mm = 2000 刻度
1 刻度 = 0.0005 mm
```

中挺宽度平分后可能产生半微米边界；派生边界和长度最多显示四位毫米小数。几何中心可能显示五位小数，仅用于定位展示，不参与下料长度计算。

坐标原点在整窗左上角，X 向右、Y 向下。与 Blender 基准坐标相比，X 相同，Y 符号相反。鼠标点击只提供候选位置，确认后的精确坐标才用于计算。

### 外框、中挺和压线

- 外框、窗扇外框使用双端 45° 斜切；清单长度是外侧长尖端到长尖端的长度，同时列出短边。
- 中挺以中心线定位，两侧各占其宽度的一半；净区域尺寸扣除中挺实体宽度。
- 中挺的先后顺序决定贯通和对接关系，可能影响下料长度。
- 压线按直角对接：横压线通长，竖压线扣除上下两根压线宽度。
- 改变整体宽高时，可保持中挺绝对坐标，或按整体宽高比例调整；比例调整对齐到 0.001 mm。非法尺寸或越界会拒绝整次修改。

### 玻璃尺寸

「玻璃宽度总减量」「玻璃高度总减量」分别设置，默认各 30 mm，独立于压线宽度。

```text
玻璃宽度 = 当前净区域宽度 − 宽度总减量
玻璃高度 = 当前净区域高度 − 高度总减量
左右每边退让 = 宽度总减量 ÷ 2
上下每边退让 = 高度总减量 ÷ 2
每边压线覆盖量 = 该边压线宽度 − 该边退让量
```

例如：净区域 462 × 500 mm，压线宽 30 mm，总减量各 30 mm，则玻璃为 **432 × 470 mm**，四边各退让 15 mm，压线每边覆盖玻璃 15 mm。压线内可见开口为 **402 × 440 mm**，与玻璃下料尺寸不同。

玻璃在分区内居中，画布绘制在压线后方。尺寸不大于零时拒绝生成；没有四边有效覆盖时会警告，并阻止玻璃排料和玻璃清单 CSV 导出。

## 型材切割

### 原料型号与库存

每个型材类别对应一个原料型号。只有**型号完全相同**的构件和原料才能匹配。

- 相同型号应代表相同截面、材质、颜色等兼容原料；系统同时校验型材宽度一致。
- 同一型号可配置多种整料长度、单价和可用根数；规格编号不能重复。
- 可用数量留空表示可采购、不限量，填 0 表示不可用。
- 「补充缺失规格」只新增缺少型号的示例 6000 mm 规格，不会自动把不同型号视为同一材料。
- 未填完单价可以保存草稿；按成本计算时，所需型号的可用规格必须填写大于零的单价。

### 锯缝与工艺损耗

采用独立切割的保守规则：

| 构件 | 锯缝预留 |
|---|---|
| 90° 直切构件 | 每根预留一道刀片厚度，末端也保留 |
| 45° 外框构件 | 每端预留 `刀片厚度 × √2`，向上取整到一个内部刻度 |
| 原料头尾修整 | 用户输入轴向总预留，已包含该端修整锯缝 |

3 mm 刀片用于 45° 构件时，每端预留 **4.243 mm**，每根共 **8.486 mm**。不共用斜口，不嵌套尖角。

每根整料满足：

```text
构件长边总和 + 工艺损耗 + 余料 = 原料长度
```

### 优化目标与结果状态

使用 OR-Tools CP-SAT，按型号分别求解：

- 最少根数：根数 → 总购料长度。
- 最低金额：采购金额 → 根数 → 总购料长度。

只有主目标取得最优证明时才显示「主目标最优」。所有优化级别均证明最优时，完整结果状态为 `OPTIMAL`；限时只找到可行方案时不会宣称最优。每个型号的求解时限可设置。

切割图及 CSV 表示轴向占用区间和加工顺序，不是某一锯机的靠尺或数控指令。

## 玻璃切割

玻璃按矩形板材进行二维排版，使用独立的刀缝参数，默认 **0 mm**，可设置 0～20 mm。

### 原板设置

填写原板的**可切净宽、净高**、单价、可用张数，以及是否允许玻璃旋转 90°。默认 2440 × 1830 mm 仅用于演示。

同一项目的玻璃原板视为同一材质和厚度。不同品种应分项目排料；需要保持纹理或加工方向时关闭旋转。当前原板尺寸不自动附加修边或磨边余量。

### 排版方法

采用 24 组确定性排序、切割方向与余料选择策略搜索方案。每块玻璃从当前矩形余料通过最多两刀贯通直切取出：

- 每刀穿透当前余料，不采用内部挖切。
- 已有原板边缘无需额外刀缝，其余切割必须预留完整刀缝。
- 放置坐标、刀缝占用和面积守恒使用整数计算。
- 刀坐标以原板左上角为原点，刀缝位于标注坐标的正方向；逐刀明细列出该刀对应的当前余料矩形。

输出采购清单、逐张排版图、每块位置、旋转标记、逐刀顺序、刀缝损耗和余料。完整 JSON 还包含矩形余料坐标。

### 最优性说明

可以选择最少张数或最低金额。搜索结果通常是可行方案，**不保证所有场景全局最优**。

仅当采购张数达到「玻璃总面积 ÷ 最大可用原板面积，向上取整」的下界时，才标注张数已证明最少；这不意味着面积或成本次目标也已证明最优。成本模式目前不提供全局最优证明。搜索未找到方案也不等于已证明无解。

## 常见问题

**提示原料型号没有可用规格？**

检查「设计参数 → 原料型号映射」与「切割排料 → 型材原料规格」。例如 `window_frame` 与 `窗户外框` 是不同字符串，不会自动混用。可点击「补充缺失规格」，再核对长度、价格和数量；如果数量全为 0，则需调整实际可用数量。加载不同窗型后尤其要检查型号匹配。

**为什么参数改了，图和清单没变？**

需要点击「应用参数并重新计算」。玻璃排料配置也有独立的应用按钮。未应用参数时，部分保存、导出或导航操作会被阻止，以免使用旧尺寸。

**玻璃为什么不是净区域减去两倍压线宽度？**

净区域减两倍压线宽度得到可见开口。玻璃还需要伸入压线后方，所以玻璃尺寸按独立的宽高总减量计算。

**保存窗型后，换浏览器找不到草稿？**

自动草稿按账号和窗型保存在当前浏览器；服务器存档通过客户、房屋项目进入。完整迁移应备份数据库，单窗可导出项目文件。

**页面提示无法连接计算服务？**

确认后端终端仍在运行，访问 <http://127.0.0.1:8010/api/health> 应返回 `{"status":"ok"}`。手机访问时将地址换为电脑局域网 IP。

**启动提示端口已占用？**

可能已有服务运行，先访问页面确认，或回到原来的终端按 `Ctrl+C` 停止后重启。

**切割结果提示未证明最优？**

这表示方案可行但缺少最优性证明。型材可尝试延长求解时限或减小批量；玻璃使用多策略搜索，其全局最优性存在上述限制。

## 当前范围与限制

- 支持矩形外框、横竖中挺、矩形分区和窗扇；不支持弧形、斜边、任意多边形或交叉穿透中挺。
- 中挺连接由区域树与绘制顺序表达，不能将任意自由线段自动解释为加工结构。
- 窗扇外轮廓与所属区域等大，尚未纳入安装间隙、搭接量、焊接余量和厂家专属扣减。
- 当前没有实际型材截面、玻璃厚度、承托、胶条或五金的三维装配校验。
- 每窗最多 100 个区域节点、24 层分隔，生产数量 1～100 樘。
- 单窗型材最多 400 根构件；整项目最多 5000 根。大规模采用有时限的可行方案，不保证全局最优。最多 40 种型材原料规格。
- 单窗玻璃最多 200 块；整项目最多 2000 块，按玻璃材料分别排版，每组最多 30 种原板规格。材料名称应明确系列、厚度和颜色。
- 余料会在方案中列出，支持在项目中手动录入已有余料参与排料；尚未实现跨订单库存台账和生产领料扣账。
- 已有登录、用户隔离和客户/项目管理；尚无离线多端同步、原生手机 App 和切割设备直连。

下料尺寸精度建立在当前几何和工艺规则之上。用于具体厂家型材生产前，应先按实际连接、装配和加工要求确认参数与样件。

### 窗型名称与整项目原料

- 新窗型默认由「楼层＋安装位置」生成名称，例如「一层·主卧东窗」。勾选「自定义名称」后可自行命名，后续修改安装位置不会覆盖名称。已有自定义名称保持不变。
- 名称输入位于上方「窗型信息」，左侧设计参数仅用于尺寸、数量和结构。名称及命名方式均随窗型保存。
- 整项目首次从各窗型汇总原料规格。型材按型号、长度和来源合并；玻璃按材料、原板尺寸和来源合并。在项目原料页添加、编辑并保存后，采用项目配置，不再自动覆盖；点击「刷新窗型数据」仅刷新窗型及尚未自定义的原料。
- 相同规格视为同一份共享库存，例如两个窗型都填 10 根，整个项目仍只有 10 根，不按窗型数量或制作数量累加。相同规格的单价、库存不一致时会提示对应窗型，需统一后保存再计算。
- 玻璃扣减尺寸仍以各窗型为准；相同材料的刀缝、旋转规则、优化目标应保持一致。项目型材切割规则可在项目排料页统一设置。

### 玻璃排版的省料判断

- 优先按所选目标比较采购张数或金额；同等采购方案下，先减少刀缝损耗，再优先保留完整的大块余料。
- “采购张数已证明最少”仅表示达到面积下界，不表示余料形状已达到全局最优；结果页显示每张原板的最大完整余料尺寸。
- 余料以逐刀贯通切割后形成的矩形为准，不能把图上相邻的空白区域直接算作一块完整余料。
- 更新排版算法后，请重启后端并重新计算；已显示或导出的旧方案不会自动改变。

### 型材排料与余料回收

- 单窗“切割工艺与目标”和整项目“项目切割规则”均可设置“可回收余料最短长度”，默认 **500 mm**；等于门槛时也计入可回收余料，设为 0 表示所有正长度余料均可回收。旧存档自动采用默认值。
- 最少根数：先减少采购根数，再减少采购总长度；最低金额：先减少采购金额，再减少根数和采购总长度。在前述目标相同的方案中，继续减少短废料，并优先留下更长的完整余料。
- 大项目比较多种构件顺序和规格选择，尝试合并原料、交换构件、替换更合适的规格；重复长度较少的批量也会进入聚合精确求解。有限库存按整个型号共享，所有锯缝及头尾修整仍计入容量。
- 结果区显示可回收余料、短废料、最长余料和回收门槛。短废料不含锯缝与头尾修整；可回收余料仅做分类，不自动写入原料库存。
- “各阶段最优”表示当前采购与余料目标均已证明最优；“主目标最优”仅保证根数或金额，“可行方案”未证明最优。时限内只返回覆盖全部构件的完整方案，已有完整解不会因后续搜索超时丢失。
- 本次涉及后端算法，更新后请停止旧进程，运行 `pwsh -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1 -SkipBuild`，刷新页面并重新计算。

### 在项目中使用已有库存余料

1. 进入房屋项目的“统一排料”，在型材或玻璃标签点击“添加库存余料”。
2. 型材选择实际兼容的型号，填写可用长度及数量。例如“窗户压线 / 1200 mm / 3 根”。玻璃在对应材料卡片内填写可用矩形宽高和张数，厚度、颜色等必须与该材料一致。
3. “需要采购”的规格可以设置单价和可采购数量上限；“已有库存”必须填写 0～500 的有限数量，不计本次采购费用。相同尺寸的不同库存行代表独立批次，请勿将同一批余料重复录入。
4. 点击“保存并计算全部型材/玻璃”。主目标只计算新增采购根数、张数或金额，再比较新料长度或面积等后续目标；不会把领用库存也算成采购。结果分别列出采购清单、库存本次使用量和未领用数量。
5. 项目中添加或编辑的配置仅影响当前项目，不修改原窗型。保存型材配置不会覆盖未保存的玻璃配置，反之亦然。反复计算不扣库存；“未领用数量”不包含本次切割新产生的余料，后者在逐根/逐板方案中查看。

这是项目试算配置，并非全局库存台账；同一批余料用于多个项目时，需自行核对实际可用数量。升级后首次连接数据库会自动增加项目配置标记，旧项目仍沿用窗型汇总。请重启后端、刷新页面再使用。
