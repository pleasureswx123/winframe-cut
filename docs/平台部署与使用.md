# 窗序多用户平台：部署与使用

本版本包含操作平台 `/` 和管理平台 `/admin.html`。二者共用 FastAPI 与 SQLite。默认运行在单实例服务和持久磁盘上；不要让多个无共享磁盘的云实例分别写各自数据库。

## 安装与启动

在仓库根目录运行：

```powershell
npm ci
npm run build
.\.venv\Scripts\python -m pip install -r requirements.lock.txt
$env:WINFRAME_DB = 'D:\winframe-data\projects.db'
.\.venv\Scripts\python -m uvicorn backend.main:app --host 127.0.0.1 --port 8010
```

首次使用需先建立 Python 3.12 虚拟环境：`python -m venv .venv`。本地可继续使用仓库的启动脚本。前端构建会同时生成 `dist/index.html` 与 `dist/admin.html`；不要只发布其中一个。

需要手机访问时，使用可信局域网地址，并将监听地址改为 `0.0.0.0`。生产通过 HTTPS 反向代理提供访问，同一站点代理 `/api`，配置：

```powershell
$env:WINFRAME_PUBLIC_ORIGIN = 'https://你的平台域名'
$env:WINFRAME_COOKIE_SECURE = 'true'
```

`WINFRAME_PUBLIC_ORIGIN` 必须与浏览器实际访问的协议、域名和端口一致，不带路径。HTTP 本机调试不要设置 Secure Cookie，否则浏览器可能无法保持登录。会话 Cookie 为 HttpOnly、SameSite=Lax，写请求还需要登录响应提供的 CSRF 令牌。

veFaaS 继续采用 `sh build.sh`、产物 `.vefaas/artifact`、`sh run.sh`。正式使用必须配置持久化 `WINFRAME_DB`；默认 `/tmp/winframe/projects.db` 仅供临时试运行，实例销毁会丢失文件。上线前需验证部署平台的持久卷和单实例策略；本次交付没有执行云部署。

## 平台地址与账号发放

按上方命令启动后：

- 制作平台：`http://127.0.0.1:8010/`
- 管理平台：`http://127.0.0.1:8010/admin.html`
- 默认超级管理员：账号 `admin`，初始密码 `admin123`。

服务启动时仅在 `admin` 不存在时创建超级管理员，已有账号的密码和名称不会被重置。如果升级前普通用户占用了 `admin`，启动会明确报告冲突，不会将该普通用户自动提升权限。

制作端不开放注册。管理员登录管理端，进入“用户管理 → 添加用户”，填写用户名、显示名称、初始密码（10～128 位），再将账号发放给用户。普通用户仅能登录制作端，并管理自己的数据。

打开 `/admin.html` 登录。管理员可以查看所有用户的客户、房屋和窗型，并启用／禁用普通用户。禁用立即撤销该用户已有会话。管理员不能在该页面禁用管理员账号。

## 升级旧数据库与备份

升级前先停止服务，再复制数据库文件到安全位置。默认路径是仓库 `data/projects.db`，如果设置了 `WINFRAME_DB`，以该路径为准。

```powershell
# 停止服务后执行；按实际目录调整。
Copy-Item -LiteralPath 'D:\winframe-data\projects.db' -Destination 'D:\winframe-backups\projects-before-platform.db'
```

新程序第一次连接数据库时在事务内执行版本迁移。旧 `projects` 表及其原始 JSON 保留，旧窗型复制到无主存档区，编号不变；重复启动不重复复制。普通用户看不到无主存档。

管理员在“平台总览 → 历史窗型待归属”中，选择所属用户和其房屋项目，再确认分配。目标用户应先建立客户和房屋。分配后该用户即可编辑旧窗型，重复分配会拒绝。

回滚需要停止新服务，保留当前数据库另作备份，然后将升级前备份恢复到原路径并运行旧代码。升级后新增的账号、客户与窗型不包含在旧备份中，回滚前应导出需要保留的资料；不要让旧版本直接写新数据库。

浏览器旧草稿不自动交给任意注册用户。在新工作台点击“导入本机旧草稿”，确认所属后导入当前项目。版本 1 的 `.winframe.json` 文件仍可通过“导入”使用。新草稿按账号与窗型分别保存；退出不会把草稿提供给其他账号。

## 日常业务流程

1. 管理员在后台添加用户并发放账号，用户登录制作平台后创建自己的客户资料。
2. 进入客户的“管理房屋”，新增房屋项目，填写地址和户型描述。同一个客户可有多个项目。
3. 进入项目新增窗型，填写楼层、房间／安装位置、玻璃材料，设置尺寸、分区及生产数量。编辑尺寸后先应用参数，再保存窗型。
4. 如需边设计边建立新客户，可在工作台点击“新建客户与项目”，把当前设计作为新项目的新窗型保存，原存档保留。
5. 项目列表中的“单窗排料”仅计算该窗型乘以生产数量；工作台切换型材与玻璃标签分别计算。
6. 项目详情的“整项目统一排料”读取整个项目所有已保存窗型。浏览器内未保存的修改不参加计算。

## 材料与统一排料

同一型材型号必须代表可互换的系列、颜色和规格。同型号条宽冲突会拒绝计算；不可互换材料请使用不同型号，不能仅依靠备注区分。

每个窗型填写玻璃材料标识，例如“透明 5mm”“磨砂 6mm”。整项目页按这些标识配置各组原板、价格、库存、刀缝与旋转规则。旧窗型默认是“默认玻璃”，正式生产前应核对材质和厚度。

“补充示例原料”只提供可编辑的示例长度／原板尺寸，不是实际厂家规格。原料库存为空表示可采购、不限量；0 表示不可用。整项目库存由全部窗型共用，不会把各窗型库存相加。按金额排料要求相关原料填写大于零的价格。

项目中的不同窗型会共同利用原料余量。结果和导出保留窗型、楼层、房间、制作实例序号及原构件编号。玻璃整块直接使用、不需要切刀时，CSV 仍输出“整块使用（无需切割）”记录。

单窗保留 400 根型材、200 块玻璃的计算上限。项目排料上限为 5000 根型材、2000 块玻璃；超限明确报错，不截断数据。小规模型材使用约束求解，大规模使用有界时间的可行排料。玻璃采用贯通直切多策略搜索。界面会区分已证明主目标最优与可行方案；未找到方案不一定代表已证明无解。

## 导出和加工核对

窗型“导出项目”保存设计、原料和工艺设置。排料结果支持 CSV、JSON 和浏览器打印。型材图展示毛坯区间、锯缝和修整；玻璃图展示原板布局与逐刀坐标。正式加工前按实际厂家规格及设备工艺核对尺寸和切割规则。

### 忘记制作账号密码

管理员登录管理平台，进入“用户管理”，点击对应普通用户的“重置密码”，输入并确认新密码（10～128 位）。确认后旧密码和该用户所有登录会话立即失效，用户需用新密码重新登录。重置不会启用已禁用的账号。系统不保存或展示原始密码；管理员账号不在此功能的重置范围内。
