# 多用户管理平台与项目排料实施计划

> **执行要求：** 使用 superpowers:executing-plans 在当前会话逐项执行；如用户选择子代理方式，则使用 superpowers:subagent-driven-development。各步骤以复选框跟踪。

**目标：** 交付共用后端的操作端与管理端，实现账号隔离、客户与房屋项目管理，以及单窗和整项目的型材、玻璃排料。

**架构：** 保留 FastAPI、SQLite 和现有几何算法，增加认证、业务层级及公共排料内核。Vue 使用双 HTML 入口与独立路由，共享基础组件和 API。所有业务归属由后端验证。

**技术栈：** Python、FastAPI、Pydantic、SQLite、OR-Tools、Vue 3、TypeScript、Pinia、Vue Router、Axios、Element Plus、Vite。

**设计依据：** [已确认设计](../specs/2026-10-12-platform-design.md)。

## 全局约束

- 中文界面、文档和新增代码注释；不改变既有尺寸整数刻度与版本 1 几何文件。
- 普通用户不得读取或修改其他用户数据；管理员跨用户浏览使用专门接口。
- 型材和玻璃都必须真正汇总后排料，并保留完整来源，不能逐窗求解后相加。
- 不修改真实 `data` 中的业务数据；迁移测试使用临时数据库。
- 保留已有绘图、导入导出、打印、手机操作及有限库存约束。
- 每步使用相关测试验证，不以构建通过代替业务验收。不推送、不部署；提交仅在用户要求时进行。

## 重点检查

1. 会话过期、切换账号时旧请求晚到，不得把前账号数据写入新会话（任务 5）。
2. 两个窗型使用相同内部构件编号，排料后不得覆盖或错认来源（任务 3、4）。
3. 不同窗型使用同一有限库存，项目排料不得重复使用库存（任务 3、4）。
4. 旧数据库重复迁移和中途失败，原存档不能丢失或自动归属于注册用户（任务 1、7）。
5. 未应用或未保存的工作台修改与服务端窗型不同，项目排料必须明确数据范围（任务 5、6）。
